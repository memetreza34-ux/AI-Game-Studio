# Roadmap – experimenteller Entwicklungsplan

**Kein fixer Release-Termin.** Jede Phase hat messbare Abschlusskriterien; erst nach Bestehen beginnt die nächste.

| Phase | Ergebnis | Abschlusskriterium |
| --- | --- | --- |
| P0 – Grundlagen | Projektauftrag, Regeln, Roadmap, Status | Dokumentation für nächste KI ohne Chatverlauf verständlich |
| P1 – Konzept & Validierung | Spielidee, Plattform, Spielschleife, risikoarme Zielgruppe | Ein einseitiges MVP-Briefing, ausgewählte Plattform, 3 Vergleichsideen |
| P2 – Toolchain-Proof | Editor/MCP und lokaler Test | Agent kann eine kleine Änderung durchführen; Test im Editor nachgewiesen |
| P3 – Playable MVP | Voller Kern-Loop | Start, Ziel, Verlust/Gewinn, Neustart, verständliche Steuerung |
| P4 – Politur & Test | Weniger Bugs, besseres Onboarding | dokumentierte Testfälle, Feedback, Performance-Check, keine kritischen Bugs |
| P5 – Veröffentlichung | Ein freigegebenes Spiel auf der Plattform | Eigentümerfreigabe, Regelprüfung, tatsächlicher öffentlicher Link |
| P6 – Lernen & Iteration | echte Nutzungs-/Retention-Erkenntnisse | Kennzahlen mit Zeitraum und Quelle, priorisierte Verbesserungen |

## P0 – Startbasis
- [x] README und gemeinsame Agentenanweisungen
- [x] Ziele, Status, Entscheidungen, Roadmap und Qualitätsanforderungen dokumentieren
- [x] Offizielle Einstiegspunkte für Tools/Monetarisierung verlinken
- [ ] Plattform-/Spielentscheidung treffen

## P1 – Konzept
- [ ] Drei Spielideen mit vergleichbaren Kriterien bewerten
- [ ] Spielfluss in 5 Sätzen beschreiben
- [ ] Zielgruppe, Geräte, durchschnittliche Rundenlänge, einzigartige Besonderheit dokumentieren
- [ ] Minimale Asset-Liste und Risikoliste erstellen
- [ ] MVP-Scope auf maximal wenige Kernfunktionen beschränken

## P2 – Technischer Proof
- [ ] Editor installieren, öffnen und Projekttyp dokumentieren
- [ ] KI-Client über offiziellen MCP-Weg verbinden
- [ ] Neue Testszene, ein Script, eine Spielaktion erzeugen
- [ ] Im echten Editor starten und Ergebnis festhalten
- [ ] Reproduzierbaren Backup-/Versionsworkflow verifizieren

## P3 – MVP
- [ ] Steuerung und Spielzustände
- [ ] Sieg/Niederlage, Neustart, einfache UI
- [ ] Balancing, grundlegende Fehlerbehandlung
- [ ] Tests von Anfang bis Ende

## P4–P6 – Veröffentlichung und Lernen
- [ ] Interne Tester, Bugs und Usability
- [ ] Alters- und Plattformrichtlinien, Assets, Datenschutzhinweise prüfen
- [ ] Faire Monetarisierung **nur falls** für Spiel und Plattform sinnvoll
- [ ] Veröffentlichung ausschließlich nach Freigabe
- [ ] Spielerzahlen, erste Sitzung, Wiederkehr und ggf. Umsatz auswerten
- [ ] Fortsetzen/verbessern/stoppen anhand von Daten, nicht Hoffnung entscheiden

**Backlog:** GitHub Issues sind die operative Aufgabenliste. Diese Roadmap beschreibt Phasen, keine detaillierte Ticket-Planung.
