# Übergabe – Standard für jeden Agentenwechsel

Eine gute Übergabe muss reichen, damit jemand ohne den vorherigen Chatkontext weiterarbeiten kann. Für jede größere Aufgabe eine kurze Übergabe in Issue/PR oder im Arbeitsprotokoll dokumentieren.

## Kopiervorlage

### Kontext und Ziel
- Thema/Issue:
- Git-Branch und Ausgangsstand:
- Gewünschtes Verhalten/Definition of Done:

### Was wurde wirklich umgesetzt?
- Dateien/Editor-Objekte:
- Wichtige technische Entscheidungen:
- Nicht umgesetzt / nicht fertig:

### Testnachweise
- Statische Prüfungen:
- Editor gestartet? Ja/Nein
- Tests mit tatsächlichen Schritten/Ergebnissen:
- Noch nicht getestete Punkte:

### Risiken und offene Fragen
- Kritische Bugs oder Datenrisiken:
- Plattformrichtlinien/Lizenzen:
- Fehlende Zugänge (keine Zugangsdaten hineinkopieren):

### Konkreter nächster Schritt
- Nächstes Issue / kleinster sinnvoller Task:
- Reproduzierbare Anleitung:
- Relevante PRs, Commits, Screenshots:

## Dauerhafte Wahrheit
- docs/STATUS.md: Zustand **des gesamten Projekts**.
- docs/DECISIONS.md: angenommene Beschlüsse.
- GitHub Issues: operatives Backlog.
- PRs und Commits: Codeänderungen.
- Game-Spec: Zustand und Anforderungen **eines** Spiels.

Nicht für jeden Chat eine weitere konkurrierende „Masterdatei“ erzeugen.
