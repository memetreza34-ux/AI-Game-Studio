# Mitwirken

## Arbeitsweise
1. Issue mit Problem, Nutzen, Akzeptanzkriterien und Abhängigkeiten wählen/erstellen.
2. Vor der Umsetzung README, AGENTS.md, Status und Entscheidungen lesen.
3. Kleine, klar benannte Änderungen auf einem eigenen Branch bevorzugen.
4. Nach Möglichkeit PR mit Beschreibung, Tests, Screenshots/Videos bei UI und bekannten Grenzen erstellen.
5. Docs aktualisieren, wenn ein Feature, ein Status, eine Entscheidung oder eine Plattformregel geändert wurde.

## Commit-Namen
Beispiele: feat: add round timer; fix: prevent double reward; docs: update roadmap; test: cover win condition; chore: adjust tooling.

## Inhaltliche Anforderungen
- Eigene/korrekt lizenzierte Assets mit Herkunft und Nutzungsrecht dokumentieren.
- Kein Kopieren fremder Spielideen 1:1, keine irreführenden Shops oder Dark Patterns.
- Bei Änderungen an Zahlungs-, Fortschritts- und Speichersystemen Testplan erstellen.
- Niemals Secrets, Echtgeld-Informationen oder reale Spielerdaten committen.
- Sprache der Projektdokumentation: Deutsch.

Siehe [Qualitätsregeln](docs/QUALITY_GATES.md) und [Agentenanweisungen](AGENTS.md).
